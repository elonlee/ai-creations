# 纠正记录

## 2026-10-18：同名项目的版本保留与删除

- 失误模式：只按首次给出的目录名处理删除，未把同名作品的实现版本与保留目标对应起来；用户随后明确要保留 Godot 版、删除原生网页版。
- 预防规则：同名作品存在多个实现时，先列清目录、实现技术、入口与共享依赖，明确对应的保留和删除范围；用户纠正后，先恢复应保留的版本，再删除目标版本，并同步迁移保留素材的来源记录及更新链接。
- 提前检测信号：首页或作品列表同时出现相同标题，目录名包含版本后缀，或某版本的文档引用另一版本的素材与记录。

## 2026-10-18：Web release 的体积预算

- 失误模式：首次导出只验证运行成功，没有拆分检查通用引擎、完整中文字库和历史资源对发布包体积的影响。
- 预防规则：发布前统计最大文件与总量，核对目标平台限制；保留运行依赖，排除历史素材，按实际界面文本生成字体子集，并将可重复的优化步骤和体积预算纳入发布检查。
- 提前检测信号：资源包包含十几 MB 的完整 CJK 字体、已停用的旧版图集，或单文件超过 GitHub 网页上传的 25 MiB 上限。

## 2026-10-18：区分可玩发布版与完整源工程

- 失误模式：把保留 Godot 版等同于保留完整开发工程，继续在展示仓库保存源码、独立素材、缓存及重复的 Web 构建。
- 预防规则：先确定仓库用途；用户只需 Web release 时，保留浏览器实际加载的文件、缩略图及许可来源记录，压缩引擎和资源并验证独立运行，再移除开发文件。
- 提前检测信号：同一目录同时存在 `project.godot`、独立 `assets/`、`.godot/` 和 `web/`，或发布包中包含完整 CJK 字体、首页截图和未使用的素材副本。
